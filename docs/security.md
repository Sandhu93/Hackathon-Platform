## Controls in place

**Security headers.** API: `Content-Security-Policy: default-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`, `Strict-Transport-Security` (2 years, includeSubDomains), `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, COOP/CORP `same-origin`, restrictive `Permissions-Policy`, `Cache-Control: no-store`. Static app (`apps/web/public/_headers`): CSP limited to `'self'` (no inline script or style), same header set, and long-lived caching only for hashed `/assets/*`. API headers are asserted in the integration tests; static-asset headers are asserted in the E2E suite and were checked with `curl` against `wrangler dev` during Milestone 00.

**CORS.** Same-origin by design. Only origins in `CORS_ALLOWED_ORIGINS` receive CORS headers; credentials allowed only for those; wildcard never used; `Vary: Origin` set. Staging/production reject non-https and local origins at config validation.

**Request IDs.** Each request has an ID returned in `X-Request-Id` and in every error body and log line. Inbound IDs are accepted only if they match `^[A-Za-z0-9._-]{8,64}$` (prevents log injection).

**Logging policy.** JSON lines with `ts, level, event, service, requestId`. Never logged: request/response bodies, headers, cookies, query strings. Every field passes through redaction: sensitive key names (`authorization, cookie, password, secret, token, otp, api key, private key, session, signature, csrf, …`), inline `key=value` secrets, `Bearer`/`Basic` credentials, JWTs, PEM private keys and long token-like strings are replaced with `[REDACTED]`; email addresses are masked to `a***@domain`; depth, size and string length are bounded. The mock email provider logs a masked recipient and the subject only — never the body (which will hold login codes). Covered by `apps/api/test/logging.test.ts`.

**Secrets.** Never committed (`.gitignore` covers `.dev.vars`, `.env*`, keys). Production secrets only via `wrangler secret put`. `pnpm security:secrets` (also in CI) scans the working tree for private keys, cloud/API tokens, service-account JSON and committed `.dev.vars`/`.env` files; deliberate fixtures need an explicit `secret-scan:allow` marker. Config validation errors report setting _names_ only, never values.

**Fail-closed configuration.** Invalid core config → generic 503 on every route (headers still applied). Provider factories refuse mocks in production and refuse real providers without credentials. `scripts/check-deploy-config.mjs` blocks deploy/migrate for staging/production while placeholders remain or production uses mock providers.

**Dependencies and supply chain.** Lockfile committed; CI installs with `--frozen-lockfile`. pnpm 12 defaults are kept: install scripts blocked except an explicit allow-list (`esbuild`, `workerd` in `pnpm-workspace.yaml`), and a minimum release age rejects versions published in the last day. `pnpm audit --prod` runs in CI (no known vulnerabilities at Milestone 00). Dependabot proposes weekly updates. Runtime dependencies are intentionally few (`hono`, `zod`, `react`, `react-dom`, `react-router`).

**Workers runtime hygiene.** Built without `nodejs_compat`; ESLint forbids Node built-ins in Worker, shared and web code; `no-console` outside the logger.

## Authentication design (Milestone 01)

**Who may sign in.** Only an address that passes _all_ of: well-formed (see normalisation), on a domain in `AUTH_ALLOWED_EMAIL_DOMAINS`, eligible under `AUTH_ELIGIBILITY_MODE`, account `active`, and a **personal** mailbox.

- `roster` (default, the safe choice): the address must already be a user row, added by an admin (single or bulk). A domain match alone is not enough, so contractors or ex-staff with a valid mailbox cannot sign in.
- `domain`: any address on an allowed domain may sign in and is created as a participant on first successful verification. A `suspended`/`revoked` row still wins and is refused. This also lets plus-tagged variants (`a+x@…`) of one mailbox create separate accounts, because plus-tags are deliberately not collapsed.
- Group/shared mailboxes (`mailbox_kind = shared`) never receive a code and never count as an administrator.

**Email normalisation.** Trim, lower-case, ASCII only, exactly one `@`, a dot-atom local part (no quoting, no consecutive/leading/trailing dots, ≤ 64), a real multi-label domain (≤ 255 total, ≤ 254 overall). **No** plus-tag stripping, no dot removal, no IDN/Unicode folding: the institution's mail system, not this app, defines which spellings are the same mailbox, and guessing wrongly would either lock people out or merge two people. The normalised form is the unique key.

**Login codes.** 6 digits from a rejection-sampled CSPRNG; valid 10 min; single use; 5 attempts; 60 s resend cooldown (all configurable). Stored only as `HMAC-SHA256(secret, "otp" | challengeId:code)`; the plaintext exists only in the outgoing email. One unconsumed challenge per address is enforced by a partial unique index, so concurrent requests cannot create parallel valid codes. Verification consumes with a single conditional `UPDATE … WHERE consumed_at IS NULL …` and checks `changes`, so exactly one of N simultaneous submissions succeeds; attempts are counted by an atomic `UPDATE … RETURNING`, so parallel guesses cannot exceed the limit.

**Sessions.** 32 random bytes (base64url) in the cookie; the database holds only `HMAC-SHA256(secret, "session" | token)`, so a database leak or backup does not yield usable cookies. Lookups join the user row and re-evaluate eligibility (status, mailbox kind, domain allow-list, role) on every request. `last_seen_at` is written at most every 15 minutes (D1 write budget).

**Why HMAC and not a password KDF.** The secrets are 6-digit codes (guessing is bounded by attempts and throttles, not by hash cost) and 256-bit random tokens (cannot be brute-forced), and the Workers free plan allows ~10 ms CPU per request, which rules out bcrypt/scrypt/PBKDF2 at useful cost. The keyed hash means a stolen database is useless without `AUTH_HMAC_SECRET`. The same key, with distinct labels (`otp`, `session`, `email`, `source`), also produces the hashes in throttle buckets and audit rows, so neither stores a plaintext address or IP.

**Secret handling.** `AUTH_HMAC_SECRET` (≥ 32 chars) is required outside development and must not be the built-in development value; otherwise every auth route returns a generic `503` (fail closed) and logs only the setting name. Rotating it signs everyone out and invalidates pending codes; no data is lost. The mock email provider is refused in production; the real provider needs `EMAIL_PROVIDER_API_KEY`, `EMAIL_API_URL` (https) and `EMAIL_FROM_ADDRESS`.

**Throttling** (fixed 1-hour windows, atomic upserts; defaults in parentheses): _request_ per address (6), per source (30), global (3000); _verify_ per address (15), per source (60), global (6000); plus the per-code attempt limit above. Checks run source → address → global and stop at the first full bucket, so a blocked caller neither consumes shared budget nor writes to the database. Source = `CF-Connecting-IP` (set by Cloudflare, not spoofable by clients; IPv6 → /64). Without that header (local development only) the source buckets are skipped.

**Audit log** (`audit_log`, append-only by convention; read via `GET /api/admin/audit`). Event types: `auth.otp.request` (`issued`, `cooldown`, `ineligible` + reason), `auth.otp.delivery` (`failed`), `auth.login` (`success`, `failure` + reason: `no_active_code`, `expired_or_exhausted`, `wrong_code`, `already_used`, `ineligible`/`suspended`/…), `auth.logout`, `auth.sessions.revoke`, `admin.user.create|update|status|role` (including `blocked_last_admin`), `admin.sessions.revoke`, `admin.bootstrap`. Rows hold ids, outcome categories, keyed hashes of address/source and the request ID; never codes, tokens, cookies, plaintext addresses or IPs. Throttled (429) requests are logged, not audited, to avoid flooding the write budget during an attack.

**Bootstrap of the first admin.** `pnpm admin:bootstrap --email … [--remote --env … --yes]` (see [deployment.md](deployment.md)). It runs from an operator's machine with Cloudflare credentials, acts only when no active admin exists (the check and the insert are one SQL statement), refuses placeholders in `wrangler.jsonc`, and audits the action. There is no HTTP route that grants the first admin.

## Known gaps and risks (Milestone 01)

| Risk                                                                                 | Severity          | Notes / plan                                                                                                                                                                                                                                                         |
| ------------------------------------------------------------------------------------ | ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Real email delivery is unverified**                                                | High (process)    | The HTTPS provider follows a common transactional-API shape but has only been tested against fakes. Do the manual real-mailbox test in [deployment.md](deployment.md) before treating production email as verified. Mail that lands in spam is invisible to the app. |
| Per-address throttle can be used to annoy a specific person                          | Low–Medium        | Anyone can burn an address's 6 requests/hour and so delay that person's own request. Mitigated by the separate per-source limit, the short window and the fact that a valid code already issued keeps working. Accepted trade-off; revisit if abused.                |
| Request/verify timing differs slightly for eligible vs ineligible addresses          | Low               | Eligible requests do extra database work and queue an email. Responses are byte-identical and verify does decoy hashing, but a patient attacker could still measure latency. Not mitigated beyond that; the roster is not highly sensitive.                          |
| Workers free-plan CPU (10 ms) and D1 write budget (100k/day) not measured under load | Medium            | Only fast HMAC-SHA256 is used and writes are minimised (15-min touch, no writes past throttle limits, opportunistic purge). Both limits are unmeasured on the deployed Worker; check CPU time in the Cloudflare dashboard during the manual test.                    |
| Fixed-window throttling allows a burst at a window boundary (up to ~2× the limit)    | Low               | Acceptable given per-code attempt limits and the 6-digit code space (1 in 200,000 per attempt, 5 attempts per code).                                                                                                                                                 |
| `domain` mode creates separate accounts for plus-tagged variants                     | Low               | Use `roster` mode (default) or normalise at the mail provider. Documented rather than guessed at.                                                                                                                                                                    |
| Rows are purged opportunistically (≈ 1 in 25 sign-ins) rather than on a schedule     | Low               | Expired challenges/sessions are inert (never accepted), so purge timing affects storage only. A Cron Trigger can take over later.                                                                                                                                    |
| A stolen cookie works until it expires or is revoked                                 | Medium (inherent) | Idle expiry 24 h, absolute 7 d, instant revocation by logout / "sign out everywhere" / admin. No device binding (it would break on mobile networks).                                                                                                                 |
| No CAPTCHA / bot detection on the request endpoint                                   | Low               | Per-source and global throttles are the control. Add Turnstile later if abuse appears.                                                                                                                                                                               |
